# Phase 1 / v0.1 experiment contract

Revised 2026-10-22 to implement the current motion-replay design.
Supersedes the previous SO-101/block/wrist-camera contract; that version remains
in Git history. Requirements below are pending, not reported results.

## Scope

One human-proportioned upper body, fixed base, articulated head and both arms,
articulated fingers, one plain scene, one fixed external camera, and a rigid
head-mounted POV camera. Use a short recorded human head-and-hand movement without
object contact. Do not replace source replay with a scripted arm policy.

Choose source movements compatible with the fixed base and available joints.
Record unachievable head translation or hand poses as residuals/failures.
No silently fabricated elbow labels, omitted head motion, or unreported clipping.

Preferred assembly: Reachy 2 plus Shadow Hands in MuJoCo, currently untested.
Start with one arm/hand. Check model licensing, attachment frames, left/right
conventions, coupled joints, collision geometry, and wrist-joint ownership.
Avoid duplicating Reachy wrist motion with Shadow wrist joints. A scripted model
smoke test is only an assembly check; Phase 1 still requires real source replay.

## Source gate

Inspect a real sample before adopting a dataset. Save its identity, recording
and session IDs, official split, source revision/hash, pose channel definitions,
units, coordinate frames, quaternion convention, timestamps, validity masks,
camera calibration if supplied, and access/use terms. Inspect individual finger
channels and tracking quality, not just wrist poses. Preserve original finger
tracking alongside robot-specific retargeted labels.
External source video is unnecessary. Source POV is a qualitative reference;
the synthetic scene does not reconstruct the original surroundings.

Choose training-eligible data for future training. Official test data may be
evaluated but must not enter training. Missing poses must be rejected or
interpolated under an explicit logged rule, with masks retained.

## Embodiment and control

Record asset revision/license, joint names and order, limits, base transform,
head-camera mount, controller settings, and all source-to-body transforms.
Use absolute joint position targets in radians for rotational joints; record
units explicitly for any translational joints.
Save source head/hand/finger poses, solved configurations, and simulator-read
joint positions separately. Mark episodes replay_mode=kinematic for direct pose
assignment. State matching its assigned configuration is not motor-tracking evidence.
Only store velocities with an explicit provenance (simulated or derived).
Dynamic control, if added, records actual states and commanded targets separately. Actual state must be read from the simulator.
Save head and hand world poses and tracking residuals for evaluation.

Select recording rates during the probe and freeze them in the manifest.
Record physics/control rates and controller settings only where applicable;
kinematic-only episodes must mark these as not applicable. Do not inherit the old 30 Hz physics assumption without testing.
Record resampling, interpolation, filtering, and action hold/substep conventions.

## Cameras and timing

Record each camera's resolution, intrinsic matrix, projection/distortion model,
near/far planes, axis conventions, parent frame, and numeric extrinsic transform.
The external camera is fixed in world coordinates. POV is fixed relative to the
head; save its changing world pose at every recorded instant.

At capture time t, freeze the simulator, read actual state q(t), and render both
cameras without advancing it. Both images and q(t) share a step ID and simulation
timestamp. If u(t) is then applied over the next control interval, store it and
the resulting next state separately: observation(t), u(t), state(t+1).
Source time is recorded separately from simulation time and wall-clock time.

The initial translator target is q(t) aligned to the external image at t, not
the next action u(t). Target commands remain available for a separate experiment.

## Raw episode

Use inspectable raw storage initially: manifest JSON, numeric Parquet tables,
and per-camera PNG images. LeRobot export comes after validation.

Required manifest data: episode/source/session IDs, split, source hash and terms
reference, scene/asset versions, transforms, joint ordering and units, replay mode,
controller settings where applicable,
timebase and sampling rules, calibration, software/device versions, and seed.

Required sample data: episode and step ID, simulation and source timestamps,
external and POV image paths/step IDs, simulator-read joint state, head/hand/finger poses,
targets with their application timestamps, source validity and retargeting errors.
If recording transitions, retain final next state and verify state chaining.
Record image hashes and render-state identifiers. Check actual rendered content
through replay and motion checks; matching IDs alone cannot detect stale buffers.

## Input isolation

Training input allowlist: external RGB clips only for the first baseline.
Known fixed calibration is renderer metadata, not per-example hidden motion.
Joint labels, source tracking, POV targets, head/hand poses, segmentation, and
other simulator diagnostics are supervision/evaluation data, never input features.
Keep object/contact/segmentation data in a separate simulator-only companion if
collected. Recordings and all derivatives must share the same split.

## Acceptance and evidence

- Source inspection is complete and the selected segment has valid head and
  both-hand and finger tracking. Record unsupported channels and select another
  segment if required motion cannot be demonstrated.
- Head, both hands, and articulated fingers show nonconstant source motion
  reproduced by the body. Include thumb/fingertip errors and self-collision checks.
- Measure hand/head position and orientation errors, discontinuities, limit
  violations, and retargeting errors. Controller tracking error applies only
  to dynamic episodes; kinematic assignment does not measure motor performance. Set numeric tolerances from the
  source precision and probe before accepting the replay; none are measured yet.
- Both camera streams reload with matching timestamps and verified content.
- Saved actual states reproduce the rendered trajectory within documented
  numerical/rendering tolerance; a checksum is not sufficient by itself.
- Save an external/POV preview and source-versus-replay pose plots.
- Save an executable command, pinned configuration, and measured frames/sec,
  simulation steps/sec, elapsed time, and resource use on the actual machine.

Phase 1 ends with one accepted replay, not a training-completion claim.
If the simulator probe blocks progress, document the failure and try the simpler
candidate while preserving the data contract. No unmeasured 16-hour switch rule.

## Deferred

Object interaction and grasping forces, block pushing, physical robots, walking, scene
reconstruction, direct neural POV generation, large-scale collection, policy
training, RL, and multi-GPU training. Phase 2 owns the small translator experiment.
