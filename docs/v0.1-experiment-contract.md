# v0.1 experiment contract

Rev B, 2026-10-21: dual-arm embodiment per operator decision (dataset alignment).
Rev A single-arm capture remains valid as harness evidence.
The earlier single-arm external/wrist capture is **Rev A harness evidence**;
it does not satisfy Rev B's embodiment or schema. Rev B has one dual-arm schema,
with no single-arm compatibility path.

Roadmap Task 1: freeze the minimal experiment. This contract uses the SO-101
scope specified for v0.1. Acceptance checks below are requirements, not results.

## 1. Scene definition

- Two identical SO-101 instances, fixed side by side at one tabletop plane.
- Source: `TheRobotStudio/SO-ARM100`,
  `Simulation/SO101/so101_new_calib.urdf`.
- Verified joint names: `shoulder_pan`, `shoulder_lift`, `elbow_flex`,
  `wrist_flex`, `wrist_roll`, `gripper`.
- Child-link chain runs from `shoulder_link` through
  `moving_jaw_so101_v1_link`; preserve the source link and joint names.
- One gripper per arm and one shared rigid block object on the tabletop.
- Both instances use URDF revision `385e8d7c68e24945df6c60d9bd68837a4b7411ae`,
  SHA-256 `3a65d2d35e68a8d2f0c2cc176d19b884506543c93ba72980145b80abe276022c`.
  Mesh hashes remain pinned in `assets/provenance.json`.
- World-frame base poses (meters, yaw about +Z): left `[-0.24, -0.12, 0]`,
  yaw `1.0471975511965976` rad (60 degrees); right `[0.24, -0.12, 0]`,
  yaw `2.0943951023931953` rad (120 degrees). Both face +Y with 30-degree
  inward yaw. The shared block starts at `[0, 0.08, 0.015]`, size
  `[0.03, 0.03, 0.03]` m, mass 0.05 kg; table plane is z=0.
- CPU FK/Jacobian probe on the merged pinned model reaches that block center
  with each `gripper_link` origin, within joint limits. Left arm five-joint
  witness: `[0.40036411, 0.99503647, -0.08559358, -0.27650544, 0]`;
  right: `[-0.40163797, 0.99499623, -0.08568237, -0.27604738, 0]`.
  Position errors are below `2e-8` m before rounding. This establishes
  kinematic workspace overlap only, not a collision-free grasp or trajectory.
  `MuJoCoEnv.reachability_probe()` repeats the probe on scratch data at reset.
- Merge method: compile the pinned URDF once with `fusestatic=false`, export
  MJCF, copy the complete `base_link` subtree left first then right, prefix
  body/joint/geom names with `left_arm/` and `right_arm/`, and share the
  identical mesh/material assets. Add the block after both arm trees.
  Assert contiguous arm qpos/qvel slices `[0:6]` and `[6:12]`; the free block
  follows them. Actuators use the same left-first order.
- Flat colors only. Record geometry, mass, friction, initial state, URDF
  revision, and random seed in the episode manifest so the scene is identifiable.

Scene exclusions:

- Arms or grippers beyond the specified pair: they add coordination variables.
- An articulated torso or head, legs, or mobile base. The fixed head-camera
  mast/body is allowed; it has no joints and is not attached to either arm.
- Additional objects or background geometry: they add contact and visibility cases.
- Deformable objects or articulated fingers: they add contact-model variables.
- Textures or photorealistic materials: they add appearance variables.
- Domain randomization: it prevents a fixed-scene integration check.
- Additional cameras, depth, or tactile sensors: they expand the observation schema.

## 3. Control contract

Joint ordering is contract law: **left arm first**, then right, each in the
Rev A raw URDF order
`[shoulder_pan, shoulder_lift, elbow_flex, wrist_flex, wrist_roll, gripper]`.
The 12 measured entries use `left_arm/` and `right_arm/` prefixes. Record both
this disambiguated order and the six raw URDF names in the manifest. Source
link/joint names remain intact after removing the namespace prefix.

- Arm commands are 10 absolute joint position targets in radians: the left
  arm's first five joints followed by the right arm's first five. They are
  not deltas, velocities, or torques.
- Gripper commands are a separate two-element normalized opening array,
  `[left, right]`: 0 = closed, 1 = open. The flattened training action is
  `[left five targets, right five targets, left opening, right opening]`,
  12 values total; this differs from measured joint order at the gripper slots.
- Store one joint-limit mapping per arm in the manifest, with gripper order
  `[left, right]` and formula
  `q_gripper_target = q_closed + opening * (q_open - q_closed)`.
  Both pinned-URDF grippers use `q_closed=-0.174533`, `q_open=1.74533` rad.
  The mock uses `[0, 1]` rad for each fake gripper and records that explicitly.
- Measured positions and velocities each cover all 12 joints, in the fixed
  order, in radians and radians/second. Measured gripper openings are a
  separate `[left, right]` pair using the respective inverse mappings.
- `left_ee_pose` and `right_ee_pose` are each position + quaternion xyzw
  (7 floats), expressed in that arm's own `base_link` frame; the MuJoCo EE
  body is that arm's `gripper_link`.
- Physics runs at 30 Hz: `physics_dt_s = 1/30`. Hold each action for N physics
  steps; v0.1 fixes `N = action_hold_steps = 1`. The control interval is
  `N/30` seconds. Record the rate and N in the manifest.

Verbatim recording rule: **Record commanded targets and measured state as
separate fields; never substitute commanded targets for measured state.**
Save the command values sent to the controller verbatim. Read measured state
from the simulator; do not copy the target into a measured field.

## 4. Timing convention and raw companion schema

At step t:

1. Freeze simulation state at `step_index = t`, `sim_time = t/30` seconds.
2. Render both cameras without advancing physics or changing scene state.
3. Read measured state from that same frozen state.
4. Apply action(t), then step physics N times while holding that action.
5. Record the measured next state, with `next_step_index = t+1` and
   `next_sim_time = (t+1)/30` seconds because N = 1.

The transition is **observation(t) + action(t) -> state(t+1)**. Both images are
pixels of one identical simulation instant, even if rendered sequentially.
The image pair precedes action(t). Every transition carries `episode_id`,
`step_index`, and `sim_time`; wall-clock render completion is not simulation time.
Object state in state(t+1) remains in the privileged companion described below.

v0.1 records raw Parquet + PNG. Paths below are relative to one episode directory.
Arrays follow the joint ordering above; PNG arrays are uint8 RGB, shape [240,320,3].

| File | Fields and types | Meaning |
| --- | --- | --- |
| `manifest.json` | `contract_revision: "B"`, `episode_id: string`, scene settings, source revision, joint order, gripper mapping, physics rate, N, camera definitions | Calibration and provenance for reload. |
| `transitions.parquet` | `episode_id: string`, `step_index: int64`, `sim_time: float64` | Unique transition key is (episode_id, step_index); time is seconds. |
| `transitions.parquet` | `external_path, head_path: string`; `external_step_index, head_step_index: int64` | Both image step IDs must equal step_index. |
| `transitions.parquet` | `command_joint_position_target_rad: float32[10]`, `command_gripper_opening: float32[2]` | Action(t), saved separately from measured state. |
| `transitions.parquet` | `measured_joint_position_rad, measured_joint_velocity_rad_s: float32[12]`, `measured_gripper_opening: float32[2]`, `left_ee_pose, right_ee_pose: float32[7]` | Observation(t) proprioception from the simulator. Each EE pose is position + quaternion xyzw in its own arm base link frame. |
| `transitions.parquet` | `next_step_index: int64`, `next_sim_time: float64`, `next_measured_joint_position_rad, next_measured_joint_velocity_rad_s: float32[12]`, `next_measured_gripper_opening: float32[2]` | Measured state(t+1), including the final transition's next state. |
| `images/external/{step_index}.png` | RGB pixels | Fixed external camera at the referenced step. |

## 5. Privileged data quarantine

Object pose, contact forces, and segmentation are flagged `sim_only` and written
to separate files, never into the policy-facing transition table or RGB images.
The manifest declares these fields and files `sim_only: true`; segmentation paths
are referenced only by the privileged companion. Record object pose as world-frame
position in meters and quaternion xyzw; contact forces use world-frame newtons.
The policy input loader uses an explicit allowlist of RGB and measured
proprioception. Privileged data is forbidden as policy input, including via a
preprocessing feature. It is available only for simulator diagnostics and evaluation.

## 6. v0.1 pass criteria

- One recorded smoke-test episode reloads from disk with every transition,
  both PNG streams, calibration, and measured next state intact. Chain check:
  `next_measured_state(t) == measured_state(t+1)` and
  `next_step_index(t) == step_index(t+1)` for every adjacent pair, so an
  off-by-one transition log cannot pass.
- For every transition, both camera streams reference identical simulation
  step IDs: `external_step_index == head_step_index == step_index`. Stamp
  check: each render call also records a checksum of the frozen state it was
  given; at validation, re-rendering from reloaded state must reproduce the
  same checksum, so stale or duplicated buffers cannot pass on labels alone.
- The scripted command sequence is nonconstant and produces measured motion:
  at least one of the five non-gripper joints **of each arm** has measured
  range >0.1 rad over the episode. A stationary arm cannot pass; movement
  of only one arm or only the grippers is insufficient.
- The training smoke test consumes the reloaded episode through the real
  data loader (no synthetic tensors), predicts recorded actions from RGB +
  measured proprioception, and completes at least two optimizer steps with
  finite loss at each step on one AMD V620 under ROCm. Record actual step
  count and losses. Use the 150 W GPU cap; CUDA-only dependencies need a
  workaround.
- If the basic check passes, run a warmed-up 500–1,000-step training run on
  the reloaded data and record its throughput; extrapolation comes from this
  warm run.
- The benchmark records frames/sec, physics steps/sec, peak VRAM, and elapsed
  seconds. Count each camera image as one frame; report counts and elapsed
  time for each measured stage, with device and software versions. There is
  no minimum throughput requirement in v0.1.
- Fallback trigger: at 16 cumulative engineering hours without working paired
  capture and episode reload, switch to MuJoCo. Record the blocker and hours;
  retain this scene, control, timing, and storage contract across the switch.

The Rev B amendment's three-command verification uses CPU physics, EGL
surfaceless Mesa llvmpipe rendering, and `--device cpu` training while vLLM
occupies the GPUs. It must not initialize HIP. This CPU training result is
integration evidence and does not satisfy the unchanged ROCm training gate
above. Its 30 measured warm steps also do not replace the 500–1,000-step gate.
Training writes `training_benchmark.json`, preserving capture `benchmark.json`
and the episode's ability to pass validation after training.

## 7. Explicitly out of scope

- Wrist-mounted cameras: useful for later robot-wrist work; Rev B uses a fixed
  head view and exactly two streams.
- Teleop: scripted commands suffice to test the recording loop.
- LeRobot export: v0.2 owns the format conversion.
- Dataset collection: one smoke-test episode checks integration.
- Policy quality: finite loss checks execution, not task competence.
- Real-time rendering: measured throughput is sufficient for this gate.
- Multi-GPU: one V620 establishes the minimum executable training path.
